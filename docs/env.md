
# `.env` Configuration Guide

*Backend Environment Variables for the ChatGPT Audio/Video Transcriber*

This file explains every environment variable required by the backend, why it matters, and how each one is used across the server, Whisper backend, Stripe billing, and password reset system.

Only developers with proper access should store or view these values. Never commit real secrets to GitHub.

---

## 1. Core Server Variables

### `PORT`

* **Purpose:** Defines the port the GraphQL server listens on.
* **Used in:** `index.js` during `app.listen(...)`.
* **Example:**

  ```
  PORT=4000
  ```

### `CLIENT_URL`

* **Purpose:** Defines the frontend origin allowed to talk to your backend (Chrome Extension, local dev, deployed UI).
* **Used in:** CORS logic, password reset links, Stripe redirect URLs.
* **Example:**

  ```
  CLIENT_URL=http://localhost:5173
  ```

---

## 2. MongoDB Connection

### `MONGO_URI`

* **Purpose:** Connection string for your MongoDB instance.
* **Used in:** `config/db.js` to initialize the database connection.
* **Example:**

  ```
  MONGO_URI=mongodb+srv://user:pass@cluster.mongodb.net/dbname
  ```

---

## 3. JWT + Authentication

### `JWT_SECRET`

* **Purpose:** Secret used to sign and verify JWT tokens.

* **Used in:**

  * `resolvers.js` (login, register, auth context)
  * `auth.js` (token verification)

* **Example:**

  ```
  JWT_SECRET=somerandomlongsecretstring
  ```

If this value changes, all existing tokens immediately become invalid — which is a feature, not a bug.

---

## 4. Stripe Billing System

### `STRIPE_SECRET_KEY`

* **Purpose:** Your private Stripe key used to create:

  * Checkout sessions
  * Payment intents (donations)
  * Subscription lookups
  * Webhook event verification (indirectly)

* **Used in:**

  * `resolvers.js` → `startSubscription`, `donate`, `cancelSubscription`
  * `webhook.js` (via `stripe` instance)

* **Example:**

  ```
  STRIPE_SECRET_KEY=sk_live_xxx
  ```

### `STRIPE_PRICE_ID`

* **Purpose:** Price ID for your subscription product.
* **Used in:** `startSubscription` resolver.
* **Example:**

  ```
  STRIPE_PRICE_ID=price_12345
  ```

### `STRIPE_WEBHOOK_SECRET`

* **Purpose:** Validates incoming Stripe webhook signatures.
* Prevents fraud, replay attacks, and requests coming from non-Stripe servers.
* **Used in:** `routes/webhook.js`.
* **Example:**

  ```
  STRIPE_WEBHOOK_SECRET=whsec_abcd1234
  ```

---

## 5. Email System (Password Reset Flow)

### `EMAIL_USER`

* **Purpose:** The email account used to send password reset emails.
* **Example:**

  ```
  EMAIL_USER=your_email@yahoo.com
  ```

### `EMAIL_PASS`

* **Purpose:** App password generated by Yahoo (not your actual login password).
* **Used in:** `nodemailer.createTransport`.
* **Example:**

  ```
  EMAIL_PASS=abcdefg1234567
  ```

---

## 6. Whisper Server Integration

These variables are read by your standalone Whisper transcription server (the audio processor).

### `OPENAI_API_KEY`

* **Purpose:** Secret key for OpenAI requests.
* **Used in:**

  * Whisper transcription server `server.js` (transcribe endpoint)
  * Chrome extension backend `POST /api/ai/summarize` route

* **Example:**

  ```
  OPENAI_API_KEY=sk-openai-xxxx
  ```

### `BACKEND_GRAPHQL_URL`

* **Purpose:** URL where the Whisper server sends:

  * Usage checks (`getUsageCount`)
  * Usage increments (`incrementUsage`)
* **Example:**

  ```
  BACKEND_GRAPHQL_URL=https://your-backend.com/graphql
  ```

This is the glue between your Whisper server and the GraphQL API.

### `OPENAI_MODEL`

* **Purpose:** Optional model override for `POST /api/ai/summarize`.
* **Default:** `gpt-5-mini`
* **Example:**

  ```
  OPENAI_MODEL=gpt-5-mini
  ```

### `MAX_TRANSCRIPT_CHARS`

* **Purpose:** Maximum transcript length accepted by `POST /api/ai/summarize` before calling OpenAI.
* **Default:** `50000`
* **Example:**

  ```
  MAX_TRANSCRIPT_CHARS=50000
  ```

# How Your `.env` Values Interact

Here’s the real value: understanding **how the secrets talk to each other**.

| Secret                      | Purpose                                   | Touches                 | Why It Matters                         |
| --------------------------- | ----------------------------------------- | ----------------------- | -------------------------------------- |
| `PORT`                      | Start server on correct port              | index.js                | Deployment environment flexibility     |
| `CLIENT_URL`                | CORS, password reset link, Stripe success | index.js, email, Stripe | Prevents blocked cross-origin requests |
| `MONGO_URI`                 | Connect to user database                  | db.js                   | Users, tokens, usage count             |
| `JWT_SECRET`                | Sign/verify auth tokens                   | login, auth.js          | Core security layer                    |
| `STRIPE_SECRET_KEY`         | Create subscriptions and payments         | resolvers, webhook      | Handles money safely                   |
| `STRIPE_PRICE_ID`           | Subscription plan ID                      | resolvers               | Which plan users buy                   |
| `STRIPE_WEBHOOK_SECRET`     | Validate webhook signatures               | webhook.js              | Prevent fake Stripe events             |
| `EMAIL_USER` / `EMAIL_PASS` | Send recovery emails                      | requestPasswordReset    | Required for password resets           |
| `OPENAI_API_KEY`            | Whisper transcription                     | Whisper backend         | Audio transforms into text             |
| `BACKEND_GRAPHQL_URL`       | Usage checking                            | Whisper backend         | Enforces token limits                  |

# Final `.env.md` Summary

The `.env` file defines:

* Server configuration
* MongoDB credentials
* Token signing key
* Stripe billing system integration
* Password reset email credentials
* Whisper transcription API keys
* URLs tying the whole system together

It is the central point where your backend, Whisper service, Stripe, and Chrome extension all connect.
